Data types and I/O

The TimeSeries, FrequencySeries and Spectrogram types, GWOSC and frame-file I/O, the download cache, and published posterior samples.

GravitationalWaveData.Types.FrequencySeries — Type
FrequencySeries{T,V<:AbstractVector{T}}

A uniformly-sampled frequency-domain series: data (length N, real or complex T, e.g. the output of FFTW.rfft) sampled every df Hz starting at frequency f0 (usually 0.0). Bin k (1-based) is at frequency f0 + (k-1) * df.

FrequencySeries(data, f0, df; name=nothing)
FrequencySeries(data, df; name=nothing)   # f0 defaults to 0.0
source
GravitationalWaveData.Types.TimeSeries — Type
TimeSeries{T,V<:AbstractVector{T}}

A uniformly-sampled time-domain series: data (length N, real or complex T) sampled every dt seconds starting at GPS epoch t0. Sample k (1-based) occurs at GPS time t0 + (k-1) * dt.

V is kept as a free type parameter (rather than hardcoding Vector{T}) so views, ranges, and (eventually) GPU arrays can be stored without an extra copy.

Construct either with dt or sample_rate:

TimeSeries(data, t0, dt; name=nothing)
TimeSeries(data, t0; sample_rate=..., name=nothing)

name is optional free-text metadata (e.g. a channel name like "H1:STRAIN"); it participates in show but not in arithmetic/equality-of-sampling checks.

GravitationalWaveData.Types.crop — Function
crop(ts::TimeSeries, t_start=nothing, t_end=nothing) -> TimeSeries

Restrict ts to the half-open GPS time window [t_start, t_end), snapping each bound to the nearest sample (the same rounding condition_segment uses). Either bound may be omitted (nothing, the default) to mean "start of the series" / "end of the series" respectively. Throws ArgumentError if the resulting range is empty or falls outside ts's coverage.

source
GravitationalWaveData.Types.crop — Function
crop(fs::FrequencySeries, f_start=nothing, f_end=nothing) -> FrequencySeries

Restrict fs to the half-open frequency window [f_start, f_end) Hz, snapping each bound to the nearest bin. Either bound may be omitted (nothing, the default) to mean "first bin" / "last bin" respectively. Throws ArgumentError if the resulting range is empty or falls outside fs's coverage.

GravitationalWaveData.Types.duration — Method
duration(ts::TimeSeries) -> Float64

Span of the series in seconds, length(ts) * ts.dt (i.e. t0 to t0 + duration, half-open – matches length(ts) == round(Int, duration(ts) / ts.dt)).

GravitationalWaveData.GWOSC._gwosc_download — Method
_gwosc_download(url, cache_dir; force=false) -> path

Download url (a GWOSC strain file or other data-release URL) into cache_dir, named after the URL's own filename (see _url_filename; GWOSC and catalog filenames already encode detector/GPS-start/duration/rate/version, e.g. H-H1_LOSC_4_V1-1126256640-4096.hdf5, so this is a natural content-addressed cache key). If a same-named file already exists in cache_dir and force=false, the network is skipped entirely and the cached path is returned. Downloads to a .part sibling file first and mvs it into place on success, so a failed/interrupted download never leaves a corrupt file at the cache path.

GravitationalWaveData.GWOSC.condition_segment — Method
condition_segment(ts::TimeSeries; trigger_time, duration=4.0, post_trigger=2.0, alpha=0.2)
    -> TimeSeries

Slice a trigger-relative analysis segment out of a full strain TimeSeries and apply a Tukey window (DSP.Windows.tukey, alpha default matching common LIGO/bilby conditioning practice): duration total seconds, ending post_trigger seconds after trigger_time (so the segment starts at trigger_time - (duration - post_trigger)).

Only the DATA segment is windowed here – the frequency-domain waveform TEMPLATE evaluated downstream is analytic and is not (and should not be) windowed; this asymmetry (tapered data, un-tapered analytic template) is standard practice in matched-filter GW parameter estimation, not an oversight.

GravitationalWaveData.GWOSC.fetch_open_data — Method
fetch_open_data(event, detector; sample_rate=4096, duration=nothing, version=nothing,
                 cache_dir=<user cache>, host="https://gwosc.org", force=false) -> String

Download the official GWOSC event-data-release strain HDF5 file for event (e.g. "GW190412", matched against GWOSC's event commonName/dataset key/GWYYMMDD prefix, following the highest available catalog version unless version is given) and detector, returning a local file path directly consumable by load_gwosc_strain.

Events typically offer several segment lengths (e.g. a short ~32s release alongside the full science-run file); duration (seconds) selects one exactly, defaulting to the shortest available match at sample_rate (the common case: a small smoke-test/quick-look segment rather than the full 4096s file). See this module's docstring above for the exact GWOSC endpoints queried.

GravitationalWaveData.GWOSC.fetch_open_data — Method
fetch_open_data(detector, gps_start, gps_end; sample_rate=4096, version=nothing,
                 cache_dir=<user cache>, host="https://gwosc.org", force=false) -> String

Download the official GWOSC science-run strain HDF5 file whose coverage fully contains [gps_start, gps_end) for detector (e.g. "H1", "L1", "V1"), returning a local file path directly consumable by load_gwosc_strain – this function only gets the bytes onto disk, it doesn't parse them (that's already solved).

GWOSC's public science-run archive is split into fixed-length (typically 4096s) segment files, so this only succeeds when the requested range falls within a single such segment; it raises a clear ArgumentError (not a partial/silently-wrong download) if no single hdf5 file at sample_rate fully covers the request. version, if given, additionally requires the chosen file's name to carry that data-release version tag (_V<version>-/_R<version>-, GWOSC's own file-naming convention).

Downloaded files are cached under cache_dir (default gravitationalwavedata_cache_dir("strain"), i.e. ~/.cache/gravitationalwavedata/strain unless GRAVITATIONALWAVEDATA_CACHE_DIR or XDG_CACHE_HOME is set; see gravitationalwavedata_cache_dir) keyed by GWOSC's own filename; a repeat call for the same file re-does the (cheap, small-JSON) locator query but skips re-downloading the (potentially large) strain file itself, unless force=true. See this module's docstring above for the exact GWOSC endpoints queried.

source
GravitationalWaveData.GWOSC.gravitationalwavedata_cache_dir — Method
gravitationalwavedata_cache_dir(subdirs...) -> String

Root of GravitationalWaveData.jl's download cache, optionally joined with subdirs. Resolved in order:

  1. ENV["GRAVITATIONALWAVEDATA_CACHE_DIR"], if set;
  2. $XDG_CACHE_HOME/gravitationalwavedata, if XDG_CACHE_HOME is set;
  3. ~/.cache/gravitationalwavedata.

The directory is a plain tree of files under their upstream names, so other tools can read it directly. Subdirectories: strain/ holds GWOSC strain files downloaded by fetch_open_data, and posteriors/ holds parameter-estimation releases downloaded by fetch_posterior_samples. The path is not created by this function.

GravitationalWaveData.GWOSC.load_gwosc_strain — Method
load_gwosc_strain(path) -> (strain::TimeSeries{Float64}, dq_mask::TimeSeries)

Read a standard GWOSC/LOSC HDF5 strain file, returning two TimeSeries:

  • strain: the /strain/Strain dataset, with t0/dt taken from that dataset's own Xstart/Xspacing attributes (not /meta/GPSstart directly – both agree in every file checked so far, but the dataset's own attributes are the authoritative source for the sample grid).
  • dq_mask: the per-second data-quality bitmask /quality/simple/DQmask, as its own TimeSeries anchored to the same GPS epoch as strain but with its own (typically 1.0s) sample spacing read from the file rather than assumed.

The DQ mask is returned as a second TimeSeries rather than bundled as metadata on strain, since it is itself a uniformly-sampled GPS-anchored series (just at a coarser rate) and gets times()/crop() for free this way – e.g. crop(dq_mask, t0, t1) to pull the DQ bits covering an analysis segment.

GravitationalWaveData.Posteriors.fetch_posterior_samples — Method
fetch_posterior_samples(event; version=nothing, cache_dir=gravitationalwavedata_cache_dir("posteriors"),
                        host="https://gwosc.org", force=false) -> String

Download the preferred published posterior-sample release for event (e.g. "GW150914", matched as in fetch_open_data's event method) and return the local file path. GWOSC catalog versions are tried highest-first, and the first one whose preferred PE analysis has an HDF5 data release is used, so recent events resolve to their GWTC-2.1/GWTC-3 PESummary files. version restricts the search to one GWOSC event version.

Files are cached under cache_dir by their upstream file name; a cached file is returned without re-downloading unless force=true. Read the result with list_posterior_analyses and load_posterior_samples.

GravitationalWaveData.GWF._decompress_frvect — Method
_decompress_frvect(raw::Vector{UInt8}, compress::Integer, ::Type{T}, nData::Integer) -> Vector{T}

Turn an FrVect's on-disk data bytes into nData samples of type T. Only compress codes 0/256 (raw) and 1/257 (gzip) are implemented – confirmed (see module docstring) to be the only schemes GWOSC's public data actually uses; every other code in _COMPRESS_NAMES raises a clear error instead of silently misinterpreting zero-suppressed or gzip-differential data as raw bytes.

GravitationalWaveData.GWF.load_gwf_strain — Method
load_gwf_strain(path; channel=nothing) -> TimeSeries{Float64}

Read a real-valued time-series channel out of a LIGO/Virgo IGWD frame (.gwf) file, following LIGO-T970130-v2 (see this module's docstring for the exact subset of the spec implemented and its scope limits: little-endian frames, FrProcData/FrAdcData channels matched to their FrVect by name rather than by resolving the full pointer graph, raw/gzip compression only).

channel, if given, must exactly match one of list_gwf_channels(path). If omitted, this looks for a unique channel whose name contains "STRAIN" (case-insensitive) – GWOSC's convention for its public strain channels (e.g. "H1:LOSC-STRAIN", "H1:GWOSC-4KHZ_R1_STRAIN") – and errors, listing the channels found, if that isn't unique.

A multi-frame file's chunks for the chosen channel are concatenated in file order; this errors if their sample spacing (dt) differs, or if consecutive chunks aren't exactly time-contiguous (no gap-filling/overlap-resolution is attempted).
