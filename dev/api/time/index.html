Time and segments

GPS/UTC conversion with leap seconds, Segment/SegmentList algebra, and Greenwich mean sidereal time.

GravitationalWaveData.GPSTime.GPS_EPOCH — Constant
GPS_EPOCH :: DateTime

GPS time's epoch: 1980-01-06T00:00:00 UTC (the start of GPS week 0). By definition, GPS time equals UTC at this instant (GPS - UTC = 0).

source
GravitationalWaveData.GPSTime.gps_to_utc — Method
gps_to_utc(gps::Real) -> DateTime

Convert GPS seconds (elapsed SI seconds since GPS_EPOCH) to a UTC date/time, leap-second aware via LEAP_SECOND_TABLE. Rounds to the nearest millisecond (DateTime's resolution limit).

source
GravitationalWaveData.GPSTime.leap_seconds — Method
leap_seconds(gps_or_utc) -> Int

GPS - UTC in whole seconds, as of the given instant (either a GPS time in seconds, Real, or a UTC DateTime). This is 0 at GPS_EPOCH and increases by 1 at each historical leap-second insertion (see LEAP_SECOND_TABLE).

source
GravitationalWaveData.GPSTime.utc_to_gps — Method
utc_to_gps(t::DateTime) -> Float64

Convert a UTC date/time to GPS seconds (elapsed SI seconds since GPS_EPOCH), leap-second aware via LEAP_SECOND_TABLE. Sub-millisecond precision is not representable (DateTime's own resolution limit); this is not a concern for GW analysis timescales.

Caveat shared by essentially every such converter: DateTime cannot represent the leap second itself (23:59:60) since Julia's Dates module has no notion of leap seconds – only ordinary instants strictly before or after an insertion are meaningful inputs here.

A sorted, coalesced list of Segments: constructing from any iterable of Segments sorts by start time and merges overlapping-or-touching segments into one, as a maintained invariant (so every SegmentList a caller holds is always already in canonical form – no separate "did you remember to coalesce?" step).

GravitationalWaveData.Segments.coalesce_segments — Method
coalesce_segments(segments) -> SegmentList

Sort segments (any iterable of Segment) and merge overlapping-or-touching ones. Equivalent to SegmentList(segments) – provided as an explicitly-named entry point since "coalescing" is a named operation callers reach for directly (e.g. after collecting raw candidate segments from a DQ-bitmask scan).

GravitationalWaveData.Segments.gaps — Method
gaps(sl::SegmentList) -> SegmentList
gaps(sl::SegmentList, bound::Segment) -> SegmentList

The complement of sl: time NOT covered by any of its segments.

Without bound, only the "internal" gaps strictly between sl's first and last segment are returned (there is no well-defined gap before the first or after the last segment when the list's own extent is the only reference frame).

With an explicit bound, the complement is computed within [bound.start, bound.stop) – e.g. gaps(good_data_segments, Segment(analysis_start, analysis_end)) to find the vetoed time within a specific analysis window, including any leading/trailing gap against that window's edges. sl's segments are clipped to bound first (segments partially or fully outside bound are handled correctly).

source
GravitationalWaveData.Segments.overlaps — Method
overlaps(a::Segment, b::Segment) -> Bool

Whether the two half-open intervals share any point. Merely touching (a.stop == b.start) does NOT count as overlapping here (no shared point in a half-open interval) – but touching segments are still merged by coalesce_segments/SegmentList, which is the more permissive, canonicalizing notion of "adjacent enough to combine" that segment-list libraries conventionally use.

GravitationalWaveData.SiderealTime.UTCTime — Type
UTCTime

Broken-down UTC civil time, mirroring the fields of XLALGPSToUTC's C struct tm output that gmst's Julian-day conversion actually needs (year, month, day, hour, minute, second). sec can be 60 for a UTC leap second, matching LALSuite's convention.

GravitationalWaveData.SiderealTime._convert_civil_time_to_jd — Method
_convert_civil_time_to_jd(utc::UTCTime) -> Float64

Port of XLALConvertCivilTimeToJD (lal/lib/date/XLALCivilTime.c) – the "short" Julian Day formula valid for dates since 1900 March (LALSuite's own comment: not expected to be used before that). Julian days start at noon, hence the - 0.5.

GravitationalWaveData.SiderealTime._delta_tai_utc — Method
_delta_tai_utc(gpssec::Integer) -> Int

Port of delta_tai_utc (lal/lib/date/XLALCivilTime.c): the change in TAI-UTC exactly AT gpssec relative to gpssec - 1 (nonzero only in the single GPS second a leap second is inserted/removed; 0 otherwise). Used to detect whether UTC needs a 60th ("leap") second.

GravitationalWaveData.SiderealTime.gmst — Method
gmst(gps_seconds::Real) -> Float64

Greenwich Mean Sidereal Time, in radians, at the given GPS time. Direct port of XLALGreenwichMeanSiderealTime/XLALGreenwichSiderealTime (with equation_of_equinoxes = 0) from lal/lib/date/XLALSiderealTime.c – see this file's module docstring for why a generic astronomy package is deliberately NOT used here.

The result is NOT reduced modulo 2pi (matching LALSuite's own convention – callers that need a value in `[0, 2pi)should reduce it themselves, e.g. viamod2pi`).

gps_seconds may carry a fractional part (sub-second precision is handled the same way LALSuite's LIGOTimeGPS integer-seconds/nanoseconds split is: the integer part feeds the UTC/leap-second/Julian-day machinery which only has whole-second resolution, and the fractional part is added back in as t_lo).

source
GravitationalWaveData.SiderealTime.gps_to_utc_seconds — Method
gps_to_utc_seconds(gpssec::Integer) -> UTCTime

Port of XLALGPSToUTC (lal/lib/date/XLALCivilTime.c): converts an integer GPS second count to a broken-down UTC civil time, accounting for leap seconds via the module's LEAPS table.

LALSuite computes this via unixsec = gpssec - leapsec + XLAL_EPOCH_GPS_TAI_UTC + XLAL_EPOCH_UNIX_GPS fed to gmtime_r; Julia's Dates provides the equivalent Unix-epoch -> civil-calendar conversion (proleptic Gregorian, matching glibc's gmtime_r in the range GW data covers) via Dates.unix2datetime.
