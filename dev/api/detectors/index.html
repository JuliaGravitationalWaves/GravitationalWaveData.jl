GravitationalWaveData.Detectors.AbstractDetector — Type
AbstractDetector

Supertype of Detector (named, host-side) and DetectorGeometry (isbits, usable inside GPU kernels and Enzyme-differentiated code). Every detector function accepts either; geometry returns the underlying DetectorGeometry.

source
GravitationalWaveData.Detectors.Detector — Type
Detector(prefix, geometry::DetectorGeometry{Float64})

A named interferometer: prefix is the two-character GWOSC/channel-name prefix (e.g. "H1"), geometry its DetectorGeometry. See H1/L1/V1 for the three ready-made instances this package provides, ported verbatim from LALSuite's lalCachedDetectors table (see this file's module docstring for the exact source).

Not isbits (the prefix is a String): pass geometry(detector) into GPU kernels or Enzyme-differentiated code.

source
GravitationalWaveData.Detectors.DetectorGeometry — Type
DetectorGeometry{T}(location, response)

A gravitational-wave interferometer's geometry: Earth-centered Cartesian location vector (meters) and response tensor (dimensionless, the d^{ab} of Anderson et al. PRD 63 042003 (2001), stored as response[i][j]). Plain bits, so it can be passed to or built inside GPU kernels.

DetectorGeometry{Float32}(H1) converts a detector's geometry to another element type.

source
GravitationalWaveData.Detectors.antenna_response_gmst — Method
antenna_response_gmst(detector::AbstractDetector, ra, dec, psi, gmst) -> (Fplus, Fcross)

compute_antenna_response with the Greenwich Mean Sidereal Time (radians) given instead of the GPS time. Allocation-free and type-generic (the result's type follows the promoted argument and geometry types), so it is safe inside GPU kernels and Enzyme-differentiated code when called on a DetectorGeometry.

gmst is not reduced modulo 2pi (it is ~4e4 rad for current GPS times): pass Float32(mod2pi(gmst(gps_time))) for single-precision evaluation, or the hour angle loses ~1e-3 rad.

source
GravitationalWaveData.Detectors.compute_antenna_response — Method
compute_antenna_response(detector::AbstractDetector, ra, dec, psi, gps_time) -> (Fplus, Fcross)

Antenna pattern functions F+/Fx for a gravitational wave from sky position (ra, dec) (equatorial right ascension/declination, radians), polarization angle psi (radians), arriving at gps_time (GPS seconds). Direct port of XLALComputeDetAMResponse (lal/lib/tools/DetResponse.c), implementing Eqs. (B4), (B5), (B7) of Anderson et al., PRD 63, 042003 (2001).

Computes gmst(gps_time) (relatively expensive: leap-second table scan + Julian-day conversion) and calls antenna_response_gmst, which callers that already hold the GMST – and GPU kernels – should use directly.

GravitationalWaveData.Detectors.time_delay_from_geocenter — Method
time_delay_from_geocenter(detector::AbstractDetector, ra, dec, gps_time) -> Float64

Light-travel-time offset (seconds) between the geocenter and detector, for a gravitational wave arriving from sky position (ra, dec) (equatorial right ascension/declination, radians) at gps_time (GPS seconds). Direct port of XLALTimeDelayFromEarthCenter (lal/lib/tools/TimeDelay.c), via its XLALArrivalTimeDiff helper specialized to detector2 = earth_center = (0,0,0).

Sign convention (matches LALSuite exactly): positive when the wavefront arrives at the detector after arriving at the geocenter – i.e. t_detector = t_geocenter + time_delay_from_geocenter(...). Computes gmst(gps_time) and calls time_delay_from_geocenter_gmst.

source

GravitationalWaveData.ReferenceCurves.aligo_design_psd — Method
aligo_design_psd(f::AbstractVector{<:Real}) -> Vector{Float64}
aligo_design_psd([f0::Real,] df::Real, n::Integer) -> FrequencySeries

Advanced LIGO "zero-detuning, high-power" design-sensitivity power spectral density (strain^2/Hz), ported from LALSimulation's XLALSimNoisePSDaLIGOZeroDetHighPower (lalsimulation/lib/ LALSimNoisePSD.c) – see this file's module docstring for the exact formula, its provenance (Buonanno & Chen, Phys. Rev. D 64, 062006 (2001), quantum noise; plus a suspension/coating thermal -noise fit), and an important naming caveat (this is NOT the simpler closed-form "Ajith fit" some other codebases use under a similar name).

Valid above ~9 Hz (LALSimulation's own documented range for this model – it omits seismic/ Newtonian-noise contributions that dominate the design curve below that).

See the "Public API" note above this docstring for the DC-bin (f=0) convention used by the FrequencySeries-returning form.
