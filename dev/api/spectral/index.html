GravitationalWaveData.PSD.psd — Method
psd(ts::TimeSeries; seglen::Int, overlap::Real=0.5, method::Symbol=:median) -> FrequencySeries

Welch-method one-sided power spectral density estimate over a (typically long, off-source) TimeSeries: split into seglen-sample segments with fractional overlap, Hann-window each (DSP.Windows.hanning, also scipy.signal.welch's default). This is deliberately a different window from condition_segment's Tukey taper on the actual analysis segment – that one exists to suppress edge discontinuities in a single non-periodic segment being FFT'd once, not to run a Welch average.

method=:median (default, the standard LIGO convention) uses the per-frequency-bin median across segments rather than the mean, which is far more robust to loud transient glitches contaminating a handful of segments; debiased by the exponential distribution's ln(2) median correction (asymptotically exact for the segment counts here – O(500) segments for a 1024s off-source stretch at 4s/50% overlap – see e.g. Allen et al. 2005 for the finite-sample correction this approximates). method=:mean skips both the median and the bias correction.

Normalization is the standard density convention (scipy.signal.welch's scaling="density"): ∫psd(f) df over [0, Nyquist] approximates the time series' variance.

Returns a FrequencySeries with f0=0.0, df=1/(seglen*dt), real-valued data.

GravitationalWaveData.Coherence.coherence — Method
coherence(ts1::TimeSeries, ts2::TimeSeries; seglen::Int, overlap::Real=0.5) -> FrequencySeries

Magnitude-squared (Welch-averaged) coherence between two TimeSeries: |Pxy(f)|^2 / (Pxx(f) * Pyy(f)), real-valued, in [0, 1]. Follows scipy.signal.coherence; see this module's header comment for the normalization/averaging conventions.

Requires averaging over multiple segments to be meaningful: a single-segment estimate is trivially 1.0 at every frequency (Pxy, Pxx, Pyy all computed from the same one FFT), which is exactly why csd/coherence always mean-average over seglen-sample, overlap-fraction-overlapping segments rather than accepting seglen == length(ts).

Pxx/Pyy are computed via psd(ts; seglen, overlap, method=:mean) (mean-averaged, matching scipy.signal.coherence's own average="mean" default and keeping Pxy's numerator and Pxx/ Pyy's denominator on the exact same averaging convention); Pxy via csd. Requires matching dt/length, same as csd.

Returns a FrequencySeries{Float64} with f0=0.0, df=1/(seglen*dt).

source
GravitationalWaveData.Coherence.csd — Method
csd(ts1::TimeSeries, ts2::TimeSeries; seglen::Int, overlap::Real=0.5) -> FrequencySeries

Welch-method one-sided cross-spectral density estimate between two TimeSeries sampled on the same grid (same dt; t0 need not match – only the bin-by-bin sample correspondence used for each FFT segment matters, matching scipy.signal.csd's own lack of an epoch concept). See this module's header comment for the normalization/averaging conventions.

Segments as in psd (same _welch_starts/_welch_window helpers: seglen-sample segments, fractional overlap, Hann window), mean-averaged (not median). Complex-valued: Pxy(f) = mean_over_segments(conj(rfft(x)) .* rfft(y)) * scale, one-sided density normalization (scipy.signal.welch's scaling="density").

Returns a FrequencySeries{ComplexF64} with f0=0.0, df=1/(seglen*dt).

GravitationalWaveData.Spectrograms.Spectrogram — Type
Spectrogram{T,M<:AbstractMatrix{T}}

A uniformly-sampled time-frequency series: data is an nfreq x ntime matrix (row i, column j is the power in frequency bin i during time bin j – the same (freq, time) axis order DSP.spectrogram uses for its power field). Row i is at frequency f0 + (i-1) * df (Hz); column j is centered at GPS time t0 + (j-1) * dt (seconds) – i.e. t0 here is the GPS time of the center of the first STFT segment, not the start of the input TimeSeries, matching how DSP.spectrogram's own time field is defined (segment-center times).

Spectrogram(data, t0, dt, f0, df; name=nothing)

name is optional free-text metadata, as with TimeSeries/FrequencySeries.

Use the existing times/frequencies generic functions (this module adds methods to the ones Types.jl exports) to get the GPS time axis / frequency axis as ranges, exactly as for TimeSeries/FrequencySeries.

GravitationalWaveData.Spectrograms.spectrogram — Method
spectrogram(ts::TimeSeries; n=length(ts) >> 3, noverlap=n >> 1, nfft=DSP.nextfastfft(n),
            window=DSP.Windows.hanning, onesided=eltype(ts) <: Real,
            name=ts.name) -> Spectrogram

Short-time Fourier transform (STFT) power spectrogram of ts: n-sample segments, noverlap samples of overlap between consecutive segments, each segment windowed and FFT'd independently (no averaging across segments within a column – see the module-level note above for how this differs from a Welch/median-averaged spectrogram). Thin wrapper around DSP.spectrogram.

Defaults match DSP.spectrogram's own (n = length(ts) >> 3, 50% overlap, nfft = DSP.nextfastfft(n), window = DSP.Windows.hanning, i.e. zerophase=false). This is the standard spectral-analysis convention (window peak centered in the middle of the segment, as scipy.signal.spectrogram also uses). It is tempting to reach for DSP.Windows.hanning(n; zerophase=true) for this, since scipy's own docs call its own convention "periodic" – but DSP.jl's zerophase=true means something else entirely: per that function's own docstring, it centers the window's peak at index 1 with the negative half wrapped to the end (a zero-phase-filter-kernel arrangement in the time domain, not a windowing-for-spectral-analysis arrangement) – using it here silently redistributes power across frequency bins by up to several orders of magnitude at some frequencies.

The returned Spectrogram's GPS time axis is derived from ts.t0: DSP.spectrogram's own time field gives segment-center times in seconds relative to the start of the input signal, so Spectrogram.t0 = ts.t0 + (that first segment-center offset).

GravitationalWaveData.QTransform.qtile_data_indices — Method
qtile_data_indices(t::QTileParams) -> UnitRange-like Vector{Int}

1-based Julia indices into a normalized_fft-style one-sided FrequencySeries selecting the frequency bins this tile's window applies to: round(offset + 1 + frequency*duration) + 1. The final +1 converts 0-based to 1-based indexing; the inner +1 is an offset inherited from the original Omega pipeline, kept as-is so results match other Omega-derived implementations.

GravitationalWaveData.QTransform.qtile_energy — Method
qtile_energy(fseries_data::AbstractVector{<:Complex}, t::QTileParams) -> (energy, dt)

Un-normalized-by-median/mean tile energy: window+select the relevant bins of fseries_data (a normalized_fft-convention one-sided spectrum), zero-pad, ifftshift, inverse-FFT, and take abs2. Returns the energy vector and its sample spacing dt = duration/ntiles. The median/mean normalization is applied afterwards by q_plane_transform.
